# Что проверить на первом прогоне в песочнице

Заливщик написан по документации API v5, но ни один запрос ещё не доходил
до Директа: заявка приложения не одобрена, оба окружения отвечают ошибкой 58.
Ниже — места, где я не смог проверить payload на живом ответе. Первый
`pnpm campaign:deploy --apply --sandbox --priority 1` пройдёт по этому списку
сам, но если он упадёт — искать надо здесь, а не в структуре кампании.

## Проверено на живом API

| Что                      | Как проверено                                               |
| ------------------------ | ----------------------------------------------------------- |
| OAuth-токен валиден      | `clients.get` вернул ошибку 58, а не 53 — токен принят      |
| Обработка ошибок клиента | 58 распознана как `AuthError`, ретраев не было, exit code 2 |
| Путь до `--apply`        | скрипт доходит до первого запроса и корректно падает        |

## Не проверено — сверить на первом ответе

| Место в коде                            | Что может не совпасть                                                                                                                                 |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `deploy.ts` → `campaignPayload`         | Используется `TextCampaign`. Стратегия аккаунта — ЕПК; если нужен `UnifiedCampaign`, меняется только эта функция                                      |
| `deploy.ts` → `searchStrategy`          | Имена стратегий: `WB_MAXIMUM_CLICKS`, `HIGHEST_POSITION`, `WB_MAXIMUM_CONVERSION_RATE`, `PAY_FOR_CONVERSION`                                          |
| `deploy.ts` → `networkStrategy`         | Комбинация `NETWORK_DEFAULT` + `LimitPercent`/`BidPercent` при выключенном поиске                                                                     |
| `bid-modifiers-deploy.ts`               | `RegionalAdjustment.BidModifier` против `MobileAdjustment.BidModifierPercent` — у Яндекса тут разные имена полей для одного смысла                    |
| `bid-modifiers-deploy.ts`               | Возрастные группы: `AGE_0_17`, `AGE_25_34`, `AGE_35_44`                                                                                               |
| `extensions-deploy.ts` → `createVCard`  | Формат `WorkTime` (`0#6#10#00#21#00`) и разбор телефона на `CountryCode`/`CityCode`/`PhoneNumber`                                                     |
| `extensions-deploy.ts` → `uploadImages` | Поле `ImageData` с base64 и `AdImageHash` в ответе                                                                                                    |
| `deploy.ts` → `ads.add`                 | Набор полей `TextAd`: `VCardId`, `SitelinkSetId`, `AdExtensionIds`, `AdImageHash`                                                                     |
| `geo.ts`                                | Реальные ID Петергофа, Ломоносова, Стрельны и Красного Села в дереве регионов — берутся из `dictionaries.get`, но имена должны совпасть буква в букву |

## Чего в заливщике нет вовсе

Осознанные пропуски, а не забытое:

- **Расписание показов.** Корпоративной кампании нужны пн–пт 09:00–19:00.
  Формат `TimeTargeting.Schedule.DaysHours` я не проверял, поэтому выставляется
  руками в интерфейсе — это одна галочка на одну кампанию.
- **Автотаргетинг.** В чеклисте стоит «оставить только целевые и узкие запросы».
  В API это отдельная настройка группы, ставится руками.
- **Ретаргетинг.** Кампания пропускается, пока не появятся сегменты Метрики:
  группа без условий показа всё равно была бы невалидной. Появятся ID —
  передаются через `retargetingListIds`.
- **Кампания лагеря** заливается вместе с остальными и остаётся остановленной.
  Включать её в конце февраля.

## Порядок первого прогона

```bash
YANDEX_DIRECT_TOKEN=... pnpm yd:check --sandbox      # доступ есть?
pnpm campaign:deploy --priority 1                    # холостой прогон, посмотреть payload
YANDEX_DIRECT_TOKEN=... pnpm campaign:deploy --apply --sandbox --priority 1
YANDEX_DIRECT_TOKEN=... pnpm yd:check --sandbox      # что реально создалось
```

Если Директ отклонит объект, в ошибке будет `RequestId` — с ним можно идти
в поддержку, если текст ошибки непонятен. Заливщик падает на первом отказе
и не продолжает: половина залитой кампании хуже, чем ничего.

# ads-autopilot — декомпозиция работ

Разбивка TZ.md на эпики → таски → подтаски. Каждый эпик — независимо поставляемый
кусок; внутри эпика подтаски упорядочены по зависимостям.

**Легенда статусов:** ⬜ не начато · 🟨 в работе · ✅ готово

**Легенда параллельности:** эпики с одинаковой меткой `[wave-N]` не пересекаются
по файлам и запускаются одновременно разными агентами.

## EPIC-00 — Фундамент

**Цель:** репозиторий, из которого можно запустить процесс и прогнать тесты.
**Готово, когда:** `pnpm install && pnpm typecheck && pnpm test` зелёные, `docker compose up -d` поднимает Postgres+Redis, миграция применяется.

| # | Таска | Подтаски |
|---|---|---|
| 00.1 | Toolchain | `package.json` (pnpm, Node 22, ESM) · `tsconfig` strict + `noUncheckedIndexedAccess` · ESLint 9 flat config · Prettier · Vitest + coverage |
| 00.2 | Инфраструктура | `docker-compose.yml` (Postgres 16, Redis 7, healthcheck) · `.env.example` со всеми ключами |
| 00.3 | Конфиг | zod-схема окружения · падение на старте при кривом `.env` · `ENCRYPTION_KEY` проверяется на длину · базовые URL Директа переключаются по `YANDEX_DIRECT_SANDBOX` |
| 00.4 | Схема БД | Prisma: клиенты, доступы, бриф, кампании/группы/объявления/ключи, статистика 4 уровней, `ChangeLog`, `PendingApproval`, `ErrorLog`, `IdempotencyKey`, `UnitsLedger`, `AiRun`, `Report`, `CompetitorSnapshot`, `Lead` · миграция · seed |
| 00.5 | Общие библиотеки | `logger` с redact секретов · `crypto` AES-256-GCM (`v1.iv.tag.ct`) · иерархия ошибок (`AppError`/`ChannelError`/`AuthError`/`RateLimitError`/`OutOfUnitsError`/`GuardrailError`) · `withRetry` с полным джиттером · `dates` в МСК |
| 00.6 | Контракт каналов | `ChannelAdapter`: read (campaigns/adgroups/ads/keywords/stats/search-queries) + write (bids/budgets/pause/resume/negatives/ad-text) · `ChannelContext` с `dryRun` · реестр адаптеров |
| 00.7 | Точки входа | `apps/api.ts` (Fastify + healthz) · `apps/worker.ts` (BullMQ) · `apps/bot.ts` (grammY) · `apps/cli.ts` (ручной прогон задач, `--dry-run`) · graceful shutdown |

## EPIC-01 — Клиент Яндекс Директ `[wave-1]`

**Цель:** типизированный клиент API v5, который не сжигает units и не падает от 429/52/53.
**Готово, когда:** в sandbox создаётся кампания, отчёт скачивается и парсится, unit-тесты на бюджет units и ретраи проходят.

| # | Таска | Подтаски |
|---|---|---|
| 01.1 | OAuth | получение токена через `oauth.yandex.ru` · хранение в `ChannelCredential` (шифрованно) · заголовки `Client-Login`, `Use-Operator-Units` |
| 01.2 | HTTP-ядро | axios-инстанс на sandbox/prod · парсинг заголовка `Units: spent/remaining/limit` → `UnitsLedger` · стоп при `remaining < YANDEX_UNITS_RESERVE` · лимит 5 параллельных запросов (`p-queue`) · логирование `RequestId` |
| 01.3 | Маппинг ошибок | 52 → `OutOfUnitsError` (отложить на час) · 53 → ретрай через 1 c, до 3 раз · 152 → лог+skip · 5xx → backoff · 401 → `AuthError` + алерт |
| 01.4 | Read-методы | `Campaigns.get`, `AdGroups.get`, `Ads.get`, `Keywords.get` · пагинация по `LimitedBy` · zod-валидация ответов · батч до 10 000 |
| 01.5 | Reports | постановка отчёта в очередь · опрос до готовности (201/202 + `retryIn`) · парсинг TSV · `AttributionModel: LSC` · типы `CAMPAIGN_/AD_/SEARCH_QUERY_PERFORMANCE_REPORT` |
| 01.6 | Write-методы | `KeywordBids.set` · `Campaigns.update` (бюджет/стратегия) · `Campaigns.suspend/resume` · `Ads.update` (для модератора) · минус-слова |
| 01.7 | Адаптер | реализация `ChannelAdapter` поверх методов, dry-run возвращает план |

## EPIC-05 — Оптимизатор `[wave-2]`

**Цель:** решения, которые нельзя слить бюджет. Это самый рискованный модуль — тесты обязательны до кода.

| # | Таска | Подтаски |
|---|---|---|
| 05.1 | Предохранители | шаг ставки ≤ 30%/сут · дневной бюджет ≤ target×1.2 · глобальный `DRY_RUN` · минимум наблюдений перед решением · `GuardrailError` при нарушении |
| 05.2 | Rule-based слой | пауза при `impressions>500 & CPA>3×target` · −15% при `CPA>1.5×target & impressions>200` · +10% при `CPA<0.7×target & расход<50% бюджета` · минус-слова при `CTR<0.5% & clicks>5` |
| 05.3 | Тесты правил | таблица кейсов на каждое правило · property-тест «ни одно решение не выходит за предохранители» |
| 05.4 | ML-слой | LightGBM на истории клиента (прогноз CPA по ставке) — после накопления данных |
| 05.5 | LLM-слой | агент читает недельный контекст и корректирует решения rule/ML · обязан объяснить решение текстом в `reason` |
| 05.6 | Применение | `ChangeLog` до/после · идемпотентность через `IdempotencyKey` · rollback последнего изменения · маршрутизация крупных изменений в approval |

## Приёмка MVP (TZ §9)

1. ⬜ Кампания создаётся в песочнице Директа по команде
2. ⬜ Отчёт за вчера приходит в TG в 08:30 МСК
3. ⬜ `--dry-run` печатает список рекомендаций оптимизатора
4. ⬜ Апрув в TG работает end-to-end
5. ⬜ Дашборд показывает 30 дней истории и текущий CPA
6. ⬜ Три полных цикла ежедневной оптимизации без вмешательства
7. ⬜ Токены зашифрованы, `.env` не в git, доступ к БД ограничен

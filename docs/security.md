# Безопасность: ключ шифрования и работа с кредами

> Требуется CLAUDE.md §6. До этого файла процедуры ротации не существовало, а
> мастер-ключ имел значение по умолчанию прямо в исходниках.

## Что чем защищено

Токены доступа к рекламным кабинетам клиентов лежат в `Credential`
зашифрованными: AES-256-GCM, отдельный случайный nonce на каждую запись, тег
проверяется при расшифровке. Ключ — 32 байта, приходит **только** из
`CREDENTIALS_ENCRYPTION_KEY`.

Значения по умолчанию у ключа нет и быть не может. Раньше стояло 32 нулевых
байта: без переменной система молча шифровала токены всех кабинетов ключом,
лежащим в открытом репозитории. Сейчас отсутствие или неверный формат ключа
роняют запуск — проверка идёт при загрузке окружения, а не при первом обращении
к кредам, чтобы процесс не поднимался зелёным и не падал через час в воркере.

Проверяется и то, что строка — настоящий base64: декодер Node молча выбрасывает
недопустимые символы, поэтому парольная фраза из 44 знаков превращалась в 32
байта и проходила проверку длины, не имея нужной энтропии.

## Выпуск ключа

```bash
openssl rand -base64 32
```

Файл с ключом — `chmod 600`. Компрометация `.env` равна компрометации всех
кабинетов всех клиентов: этого достаточно, чтобы тратить их деньги.

## Ротация

**Постепенной ротации сейчас нет.** В `Credential` нет ни версии ключа, ни его
идентификатора, а процесс кеширует один ключ. Значит смена ключа обязана
проходить одномоментно, с остановкой записи, и выглядит так:

1. Снять свежий дамп: `./scripts/backup-db.sh`. Без него ошибка на шаге 4
   необратима — старые записи станут нерасшифровываемыми навсегда.
2. Остановить всё, что пишет в креды: `docker compose -f docker-compose.prod.yml stop worker bot api`.
3. Выпустить новый ключ и сохранить **оба** — старый ещё нужен.
4. Перешифровать: прочитать каждую запись старым ключом, записать новым.
   Отдельного скрипта нет — это разовая операция, и писать её надо под конкретную
   ротацию, с проверкой количества строк до и после.
5. Подменить `CREDENTIALS_ENCRYPTION_KEY`, поднять стек, убедиться, что хотя бы
   один клиент читается: `pnpm cli clients` покажет каналы, если расшифровка идёт.
6. Старый ключ уничтожить, но не раньше, чем дамп из шага 1 перестанет быть нужен.

Если ротация делается **по компрометации**, порядок другой: сначала отозвать
токены на стороне площадок (кабинет клиента → доступы приложения), и только
потом всё остальное. Перешифрованный украденный токен остаётся украденным.

## Что известно и не закрыто

Перечислено честно, чтобы не выглядело закрытым:

- **Ключа версии нет** — отсюда одномоментная ротация выше.
- **Журнал доступа не покрывает то, что произошло с секретом дальше.** Сам
  журнал теперь пишется: строка в `AuditLog` появляется на каждом чтении, записи
  и отзыве, включая промах, — запись живёт в `CredentialRepository`, единственном
  месте, где секрет расшифровывается, поэтому мимо неё не пройти. Отказ журнала
  закрытый: не записали факт выдачи — не выдали. Чего журнал не знает: расшифровав
  токен, подсистема держит его в памяти и может использовать сколько угодно раз —
  в журнале это одна строка. Он отвечает на «кто доставал», а не на «что с ним
  делали».
- **Никто не смотрит в журнал.** Строки пишутся, но ни отчёта, ни тревоги по ним
  нет: аномальный доступ увидит только тот, кто откроет таблицу руками.
- **Кеш токенов VK ключуется только по клиенту**, без учёта кабинета: после
  смены кабинета у того же клиента запрос может уйти со старым токеном, пока
  кеш не протухнет.
- **Продление токена перезаписывает payload целиком** и теряет поля, которых нет
  в схеме продления.
- **Гонка двух продлений** — read-modify-write без блокировки: один из
  refresh-токенов теряется.
- **Список `redact` в логгере** не покрывает `accessToken`/`refreshToken`/
  `clientSecret` и не разворачивает `err.config` axios. Достижимого места, где
  туда попадает секрет, сейчас нет, но защита держится на дисциплине, а не на
  конфиге.

## Правила, которые не обсуждаются

- Токен целиком в лог не попадает никогда — только последние 4 символа.
- `.env` не коммитится и не уезжает в образ (проверено `.gitignore` и `.dockerignore`).
- В `.env.example` — только имена переменных.

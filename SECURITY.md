# Security Policy

## Поддерживаемые версии

Проект в стадии активной разработки. Патчи безопасности только для последнего релиза.

## Как сообщить об уязвимости

**НЕ создавай публичный GitHub Issue** для уязвимостей.

Напиши напрямую:

- **Email:** roman.v.gudkov@gmail.com
- **Telegram:** [@Rivega42](https://t.me/Rivega42)

Включи в отчёт:

1. Описание уязвимости
2. Шаги воспроизведения (proof of concept, если возможно)
3. Возможное влияние (impact)
4. Твои контакты для обратной связи

## Что ожидать

- Ответ в течение **48 часов**
- Оценка серьёзности в течение **7 дней**
- Патч и релиз в зависимости от серьёзности:
  - **Critical** — до 24 часов
  - **High** — до 7 дней
  - **Medium** — до 30 дней
  - **Low** — в ближайшем плановом релизе

## Что считается уязвимостью

- Утечка креденшелов клиентов (токены рекламных кабинетов, платёжные данные)
- Возможность выполнения кода на сервере
- SQL injection, XSS, CSRF
- Обход системы approval (кто-то без прав меняет ставки/бюджеты)
- Race conditions при списании средств
- Injection в LLM-промпты (prompt injection с последствиями)

## Что НЕ считается уязвимостью

- DoS через большое количество API-запросов (rate limits решают)
- Ошибки валидации в UI без последствий безопасности
- Известные уязвимости в зависимостях с CVSS < 4.0 (обновляем по расписанию)
- Bug bounty пока не выплачивается

## Правила работы с секретами

Разработчикам и AI-агентам:

- **Никогда** не коммитить `.env`, `credentials/*`, приватные ключи
- **Никогда** не логировать токены целиком (только последние 4 символа)
- Токены клиентов в БД — **только зашифрованные** (AES-256-GCM)
- Мастер-ключ шифрования — только в переменной окружения
- Rotate токены раз в 90 дней (или чаще при подозрении на утечку)

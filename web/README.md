# web — дашборд ads-autopilot

Next.js 14 (App Router). Закрывает пункт приёмки ТЗ §9.5: **30 дней истории и текущий CPA по
каждой кампании**.

## Что умеет

| Экран             | Путь              | Что показывает                                                          |
| ----------------- | ----------------- | ----------------------------------------------------------------------- |
| Клиенты           | `/clients`        | имя, статус, подключённые каналы, число кампаний, расход и CPA          |
| Кампании          | `/campaigns`      | канал, статус, дневной бюджет, расход, текущий CPA и отклонение от цели |
| Карточка кампании | `/campaigns/[id]` | графики показов, кликов, расхода, конверсий и CPA за 30 дней            |
| История изменений | `/changes`        | `ChangeLog`: что изменилось, почему, кто подтвердил                     |
| Очередь апрувов   | `/approvals`      | `PendingApproval` со сроком жизни и решением                            |

Фильтры (канал, период, статус) стоят одной строкой над содержимым и живут в адресной строке —
срез можно переслать ссылкой.

## Только чтение

Дашборд ходит в БД и больше никуда. Кнопок «применить», «откатить», «одобрить» здесь нет: любое
изменение проходит через approval-флоу в Telegram-боте (ТЗ §3.2). Единственный внешний ресурс —
Postgres.

## Запуск

```bash
docker compose up -d postgres          # из корня репозитория
pnpm --filter web dev                  # http://localhost:3001
pnpm --filter web build && pnpm --filter web start
pnpm --filter web test                 # юнит-тесты чистых функций
```

Живая БД нужна только на рантайме: `build` её не трогает, все страницы `force-dynamic`.

## Переменные окружения

| Переменная            | Обязательна | Смысл                                                     |
| --------------------- | ----------- | --------------------------------------------------------- |
| `DATABASE_URL`        | да          | та же строка подключения, что у бэкенда                   |
| `DASHBOARD_PASSWORD`  | да\*        | пароль HTTP Basic                                         |
| `DASHBOARD_USER`      | нет         | логин HTTP Basic, по умолчанию `admin`                    |
| `DASHBOARD_AUTH_MODE` | нет         | `proxy` — авторизацию держит Nginx/Cloudflare (ТЗ §5, M8) |

\* Без `DASHBOARD_PASSWORD` и без `DASHBOARD_AUTH_MODE=proxy` дашборд отвечает `503`. Отказ по
умолчанию: забытая переменная не должна открыть наружу расходы клиентов.

Учётных записей и ролей нет и не планируется — это витрина на чтение, а не система доступа.

## Prisma

Схема одна на весь проект — `prisma/schema.prisma` в корне; своей у дашборда нет.

`@prisma/client`, `@prisma/adapter-pg` и `pg` намеренно не объявлены в `web/package.json`, а
резолвятся из корня воркспейса. Причина в pnpm: `@types/react` приезжает необязательным peer'ом
`prisma`, у корня он резолвится в latest, у `web` — в тот, что просит Next 14, и в сторе
оказывается два разных экземпляра `@prisma/client`. Сгенерированный клиент лежит только в одном
из них, и объявленная в `web` копия была бы пустой.

`pnpm --filter web build` сам вызывает `prisma generate` (см. `web/prisma.config.ts`);
подключения к БД генерация не делает.

## Оформление

Палитра, формы графиков и правила подписей — из dataviz-гайда: один категориальный слот на все
графики, статусные цвета отдельно от серий, тонкие марки, hairline-сетка. Тёмная тема — не
инверсия, а свои шаги тех же оттенков; переключается через `prefers-color-scheme`.

Клиентского JS почти нет: фильтры — обычная GET-форма, графики — серверный SVG, наведение
сделано на CSS. Под каждым набором графиков лежит таблица-двойник: значение, доступное только по
наведению, недоступно с клавиатуры и в печати.
